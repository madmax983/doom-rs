**Avoid returning `impl Iterator` when `level` must remain unborrowed**
**Learning:** Changing a function like `sectors_by_tag` to return an `impl Iterator` instead of a `.collect()`'d `Vec` avoids a heap allocation. However, because the iterator immutably borrows the `Level` struct, it prevents the caller from obtaining a mutable borrow on `GameState` (or anything else) if `Level` and `GameState` are heavily intertwined or if the iterator is held across mutable calls. While architectural separation of `Level` (immutable) and `GameState` (mutable) often allows this, the change must be verified against all call sites to ensure it doesn't violate borrow checker rules or break API expectations (e.g., if a caller expects to call `.len()`).
**Action:** When considering replacing a `Vec` return type with an `impl Iterator` to save allocations on a struct that is widely referenced, first verify that no caller needs mutable access to state while iterating, or requires `Vec`-specific methods like `.len()`.
