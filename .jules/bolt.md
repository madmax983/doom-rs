**[Optimizing recursive flood-fills in Rust]**
**Learning:** When performing recursive flood-fill operations over a graph stored in a mutable struct (like `GameState`), the borrow checker will prevent iterating over a reference to the graph (`&gs.links`) while simultaneously calling a function that requires a mutable reference to the struct (`&mut gs`). The initial reflex to `clone()` the slice of links appeases the compiler but introduces a devastating O(N) heap allocation inside the hot path of the recursive algorithm, defeating the purpose of the optimization.
**Action:** Always avoid cloning collections inside hot recursive loops to bypass the borrow checker. Instead, read the length of the slice (`num_links = gs.links.get(idx).map_or(0, |l| l.len())`) and iterate using a numeric index `0..num_links`, copying out only the small `Copy` values needed for the recursive call. This ensures zero heap allocations while satisfying Rust's aliasing rules.
