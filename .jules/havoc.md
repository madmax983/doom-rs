## 2024-05-18 - [Havoc: OOM on TEXTURE1 parser]
**Learning:** Doom's TEXTURE1 parsing uses a direct 4-byte `num_textures` read to allocate `Vec::with_capacity(num_textures)`. Fuzzing this length with large values triggers an immediate OOM.
**Action:** Use `.min(data.len() / 4)` to clamp lengths derived from WAD/lump headers, preventing massive allocations while still ensuring we parse valid entries up to the slice boundary.

**Blockmap Linedef Indexing Out of Bounds**
**Learning:** Returning 0 as a fallback for missing offsets in binary lump parsing leads to silently resolving to the header data at offset 0 instead of returning an empty or failing result.
**Action:** Always strictly handle out-of-bounds array or vector access by returning empty iterators or propagating errors instead of providing silent and invalid fallbacks like 0.
