# 🔭 Vantage: Spec for Safe Map Analysis

## Context

The map analysis logic occasionally crashes when attempting to analyze highly segmented or malicious maps with extreme geometric depths. The engine should not panic when given such inputs.

## 👤 User Story

"As a Player, I want the engine to gracefully handle complex or malformed map geometry, so that my game doesn't crash unexpectedly during map load."

## 🎯 The "So What?" Ask

**What business problem does this solve?**
Engine stability is a core requirement. Game crashes resulting from map topology analysis represent a critical liability that breaks the core loop, frustrating users and limiting the variety of custom maps (WADs) the engine can support. Handling extreme inputs gracefully expands our supported content library and builds player trust.

## ✅ Acceptance Criteria

### 1. Robust Topology Processing
- **Success Metric:** The map analyzer must successfully process linear or highly nested segment topologies exceeding 10,000 deep nodes without a fatal stack overflow panic.
- **Criteria:**
  - The core analysis must scale linearly or better with node count without exceeding safe recursion limits.
  - The engine must gracefully skip or error out (returning to the main menu) if a map is computationally impossible to analyze, rather than crashing.

### 2. Map Compatibility
- **Success Metric:** Existing maps, including extremely large maps, load successfully and chokepoints are correctly identified.
- **Criteria:**
  - Standard maps (like E1M1) show no difference in analyzed outputs.

## 🚫 Out of Scope

- **Real-time Re-analysis:** The map topology shouldn't be recalculated during active gameplay. Analysis remains a load-time operation.
- **Fixing Map Geometry:** The engine is not responsible for repairing malformed maps; it only needs to avoid crashing when encountering them.

## ⚖️ Gap Analysis

Currently, the analysis relies heavily on unbounded deep recursion traversing connected segments. On deep topologies (like maps generated by fuzzers or massive slaughtermaps), this triggers thread stack overflows. We need to transition the traversal strategy from call-stack dependence to explicit heap-managed state or iterative approaches to ensure absolute stability regardless of map scale.
