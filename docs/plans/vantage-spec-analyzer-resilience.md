# 🔭 Vantage: Spec for Map Topology Analyzer Resilience

## 👤 User Story
As a Modder or Player, I want the map topology analyzer to gracefully handle deeply nested or malformed maps, so that the game does not suddenly crash or crash on startup with a stack overflow.

## ❓ So What?
Currently, the map analyzer uses recursive algorithms which fail and crash the entire engine if they encounter heavily segmented or extremely deep topological maps (e.g. ones generated by fuzzers or malicious map makers). This makes the engine brittle and causes poor user experience when loading large scale or non-standard custom content. Ensuring engine resilience prevents unexpected data loss or interruption of gameplay, making the engine much more robust for the broader community.

## 📏 Metric Definition
- **Success Criteria:**
  - The map topology analyzer completes processing on extremely deep linear map topologies (e.g., 10,000+ nested sectors) without causing a stack overflow or panicking.
  - The analysis produces correct chokepoint data, consistent with shallower maps, under extreme nesting.
  - The engine continues to load the map and function correctly even under stressful input data.

## 🔍 Gap Analysis
- **Current State:** The map analyzer crashes with `fatal runtime error: stack overflow, aborting` when it encounters deeply nested maps due to recursion depths scaling linearly with the wad topology.
- **Market:** High-quality game engines like modern source ports gracefully handle large or complex custom map formats by employing non-recursive or dynamically scaled algorithms, avoiding application-crashing panics on user-generated data.

## ✅ Acceptance Criteria
- Must be able to process maps with over 10,000 connected sectors without stack overflow.
- Must return expected and accurate articulation point (chokepoint) analysis results, even for extreme topologies.
- Must ensure that any malformed map state simply returns an empty or best-effort result instead of panicking, keeping the engine process alive.

## 🚫 Out of Scope
- Optimizing the absolute wall-clock performance of the analyzer (performance is a secondary concern to resilience here).
- Complete rewrite of the analyzer feature set.
- Writing new visual rendering features based on these chokepoints.
