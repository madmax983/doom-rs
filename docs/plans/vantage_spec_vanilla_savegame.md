# 🔭 Vantage: Spec for Vanilla Savegame Compatibility

## 👤 User Story
As a Retro Gamer, I want to load my original DOS and Chocolate Doom save files (`.dsg`) in doom-rs, and save my doom-rs progress in a format they can read, so that I can seamlessly switch between engines without losing my campaign progress.

## ❓ So What?
Currently, doom-rs uses a custom binary save format (`SAVE_VERSION=3`), and saving/loading the vanilla `.dsg` format is unsupported, returning a `SaveError::UnsupportedVanillaDsg` error. A core promise of a vanilla-compatible source port is historical preservation and cross-compatibility. By not supporting the vanilla save format, we break the expected "bug-for-bug replica" and "DOS compatibility" goals outlined in our Parity Roadmap (Milestone M7), frustrating users who expect to migrate their existing saves.

## 📏 Metric Definition
- **Success Criteria:**
  - The engine can successfully load a standard `.dsg` file generated by Chocolate Doom or DOS Doom.
  - The engine can save the current game state to a `.dsg` file that can be loaded without errors in Chocolate Doom.
  - Corrupted or incompatible save files must be rejected gracefully with a user-friendly error message.

## 🔍 Gap Analysis
- **Current State:** doom-rs relies on a custom save format. While there's a stub for it (`savegame_vanilla.rs`), actual `.dsg` payload loading/saving is a placeholder returning `SaveError::UnsupportedVanillaDsg`.
- **Market / Standard Libs:** Source ports like Chocolate Doom treat vanilla `.dsg` support as a baseline requirement. Since we don't do this, we are currently behind the industry standard for retro-preservation engines as per our Parity Roadmap M7.

## ✅ Acceptance Criteria
- Must implement the vanilla `.dsg` read/write payload matching the vanilla layout and ~180 KB buffer semantics.
- Must successfully load a Chocolate-written `.dsg` into doom-rs and vice-versa.
- Must preserve player inventory, map state, and monster positions accurately.
- Must surface clear error messages if a savefile uses an unsupported version.

## 🚫 Out of Scope
- Boom-format or GZDoom-format save file support.
- Modifying the existing proprietary doom-rs save format (it remains as an alternative).
